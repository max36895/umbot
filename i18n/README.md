# Перевод документации

Источник правды — русская документация в `src/docs/`. Английская версия собирается из неё скриптом
`scripts/i18n-docs.js` и кэша переводов. Вручную английские страницы не правятся.

## Как устроено

- Страница режется на блоки: абзац, заголовок, список, таблица, блок кода. Граница блока — пустая строка.
- У блока есть хэш русского текста. Перевод хранится в `en/translations.json` под этим хэшем.
- Поправили абзац в русской доке — у него новый хэш, старый перевод в сборку не попадёт. Перевести нужно только этот
  абзац, остальные блоки страницы остаются переведёнными.
- Блок без перевода попадает в сборку на русском, `status` показывает, сколько таких блоков.
- Блоки без кириллицы (код без комментариев, таблицы API) не переводятся — они одинаковы на всех языках.

## Файлы

| Файл                   | Что это                                                            |
| ---------------------- | ------------------------------------------------------------------ |
| `en/config.json`       | Список переводимых страниц (`pages`) и плашка о машинном переводе  |
| `en/glossary.md`       | Термины и правила перевода                                         |
| `en/translations.json` | Кэш переводов: хэш → `{ ru, en }`. Хранится в git                  |
| `en/pending.*`         | Блоки, которые ждут перевода (создаёт `export`, в git не хранится) |
| `en/build/`            | Собранные английские страницы (создаёт `build`, в git не хранится) |

## Работа

```bash
node scripts/i18n-docs.js status            # сколько переведено по страницам
node scripts/i18n-docs.js export            # блоки без перевода → i18n/en/pending.md
# переводим pending.md по глоссарию: под каждой строкой <!-- block ... --> — перевод вместо русского текста
node scripts/i18n-docs.js import перевод.md  # проверки и запись в кэш
node scripts/i18n-docs.js build             # i18n/en/build/src/docs/*.md
node scripts/i18n-docs.js prune             # удалить переводы блоков, которых больше нет
```

`import` не пропускает блок, если в переводе изменился код (вызовы функций, число строк), пропали или изменились
фрагменты `кода`, числа или адреса ссылок, или осталась кириллица. Эти проверки не требуют знания английского.

## Публикация

Английский сайт `https://www.maxim-m.ru/docs/umbot/en/` собирает сервер (`server/pullDoc.sh`) из ветки актуальной
версии: копия ветки → `build --out` поверх русских `.md` → typedoc → `server/scriptDoc.js` с `UMBOT_DOC_LANG=en`.
Переводятся гайды и README; API-страницы остаются с русским JSDoc и ссылаются canonical на русский сайт. Перед
релизом все страницы должны быть на 100% (шаг 3.2 скилла `umbot-release-prepare`), иначе новые абзацы попадут на
английский сайт по-русски.

## Как проверить перевод без знания английского

1. Откройте собранную страницу и переведите её обратно Google-переводчиком: смысл должен совпасть с русской.
2. Расхождение смысла правится в кэше (`en/translations.json`) или повторным переводом блока, а не в `build/`.
