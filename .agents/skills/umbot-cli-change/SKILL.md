# CLI Change: изменения в генераторе и шаблонах umbot

## Назначение

`cli/` — не вспомогательная песочница, а **продуктовая поверхность**: ошибка в шаблоне или генераторе становится ошибкой в проекте пользователя, который тот запустит в проде (AGENTS.md раздел 1). Этот скилл — воркфлоу правок в `cli/`, отдельно от изменений фреймворка.

## Когда НЕ использовать

- Правка `src/core/` → `umbot-core-engineer`
- Новый адаптер платформы → `umbot-platform-add`
- Багфикс во фреймворке по репорту → `umbot-fix-bug`
- Подготовка релиза (синхронизация пинов версии) → `umbot-release-prepare`

## Шаг 0: прочитай `cli/AGENTS.md`

**До любых правок.** Вложенный `cli/AGENTS.md` описывает устройство генератора: ключевые функции `flowGenerator.js`, поток генерации, 16 правил генерации (экранирование, арифметика, HTTP-таймауты, секреты, защита от перезаписи, Docker) и список уже исправленных багов. Не восстанавливай эти знания заново по коду и не повторяй закрытые баги.

Этот скилл описывает **как менять**, `cli/AGENTS.md` — **что именно устроено внутри**.

## Карта CLI

| Файл / каталог                         | Что это                                                                                                                                |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `cli/umbot.js`                         | Точка входа `npx umbot`: разбор `argv`, чтение конфиг-JSON. В JSDoc-шапке — ручной `@version`                                          |
| `cli/controllers/ConsoleController.js` | Диспетчер команд и текст справки (`infoText`). `VERSION` берётся из `package.json`                                                     |
| `cli/controllers/CreateController.js`  | Команда `create`: генерация проекта из `cli/template/`, Dockerfile, файл деплоя                                                        |
| `cli/flowGenerator.js`                 | Генератор `create from-flow` (~2700 строк). `UMBOT_VERSION` берётся из `package.json`                                                  |
| `cli/utils.js`                         | Файловые хелперы CLI                                                                                                                   |
| `cli/index.ts`                         | TS-обёртка                                                                                                                             |
| `cli/template/`                        | Шаблоны генерируемого проекта (`index*.ts.text`, `package.json.text`, `tsconfig.json`)                                                 |
| `tests/cli/`                           | Тесты CLI: `flowGenerator`, `flowGeneratorUserScenario`, `flowUtilsIsEqual`, `createController`, `consoleController`, `deploySanitize` |

Команды, которые обязаны продолжать работать после твоей правки:

```
npx umbot create <имя|config.json>
npx umbot create from-flow <flow.json> [--output ./dir] [--usecloud] [--force]
npx umbot validate <flow.json>
npx umbot stats --log <path>
npx umbot add docker | deploy | env [--force]
npx umbot generateenv [--force]
npx umbot version | -v
```

Меняешь набор команд или флагов — обнови `infoText` в `ConsoleController.js`, иначе справка врёт.

## Воркфлоу

### Шаг 1: определи, что именно ломается у пользователя

Сформулируй дефект в терминах результата генерации, а не кода генератора: «в сгенерированном `src/index.ts` переменная подставляется как `undefined`», а не «в `textExpr` неверная ветка». Если дефект нельзя сформулировать так — возможно, это не баг CLI.

Для `from-flow` собери минимальный `flow.json`, воспроизводящий проблему: ровно те ноды, без которых баг исчезает.

### Шаг 2: тест до фикса

Тесты `tests/cli/` проверяют **сгенерированный текст**, а не внутренности генератора. Добавь кейс в подходящий файл (`flowGenerator.test.ts` — генерация из flow, `flowGeneratorUserScenario.test.ts` — сквозные сценарии, `createController.test.ts` — шаблонный `create`, `consoleController.test.ts` — разбор аргументов и справка) и убедись, что он падает.

Проверяй тот фрагмент кода, который получит пользователь: `expect(indexTs).toContain("bot.addCommand('start'")`. Не проверяй внутренние функции, которые завтра переименуют.

### Шаг 3: правка

Инварианты генерации (полный список — `cli/AGENTS.md`, «Правила генерации»), которые нарушаются чаще всего:

1. **Экранирование.** Любой текст из `flow.json` попадает в template literal — экранируй `` ` ``, `$`, `\`, переносы. Значение из flow не должно уметь внедрить произвольный TypeScript.
2. **Произвольный JS не исполняется.** Арифметика разбирается ограниченным парсером (числа, известные переменные, скобки, `+ - * / %`), всё остальное остаётся текстом. Не заменяй это на `eval`/`new Function`/`JSON.parse(template)`.
3. **HTTP только с таймаутом.** Сгенерированный код ходит в сеть через `fetchWithTimeout` из `utils.ts`, никогда — голым `fetch`.
4. **Секреты не в commit-prone файлах.** Реальные токены из `flow.json` не пишутся в `serverless.yml`, `package.json`, `README.md` и исходники — только ссылки на env-переменные. Токены идут в `.env`, который не коммитится.
5. **Без молчаливой перезаписи.** Непустая выходная директория перезаписывается только при явном `--force`/`options.force`, и это покрыто тестом.
6. **Сгенерированный проект обязан компилироваться** под своим сгенерированным `tsconfig.json` — с теми зависимостями, которые генератор прописал в `package.json`.

### Шаг 4: проверь оба пути генерации

`create from-flow` и шаблонный `create` — независимые ветки кода. Правка в одной не чинит другую; проверь, не нужно ли то же изменение во второй. То же касается вариантов шаблона (`indexDev*`, `indexBuild*`, `*Min`, `*Online`) — их восемь, и менять один, забыв остальные, — типовая ошибка.

### Шаг 5: верификация

Сначала обычный порядок проекта (AGENTS.md 3.6):

```bash
npm run build
npm run test
npm run prettier
npm run lint
```

Затем ручная проверка на реальном выходе — тесты не ловят проблемы сборки сгенерированного проекта:

```bash
node cli/umbot.js create from-flow <твой-flow.json> --output ./audit/tmp-bot --force
cd audit/tmp-bot && npm install && npm run build
```

`audit/` и `tmp-surgery/` — игнорируемые песочницы, генерируй туда, не в корень репозитория.

⚠️ `npm install` в сгенерированном проекте упадёт с E404, если пин `umbot` указывает на версию, ещё не опубликованную в npm. Это ожидаемо на ветке до релиза — ставь зависимость из локального tarball (`npm pack` в корне, затем `npm i ../../umbot-X.Y.Z.tgz`), а не правь пин «чтобы собралось».

### Шаг 6: версии

- `cli/flowGenerator.js` (`UMBOT_VERSION`) и `cli/controllers/ConsoleController.js` (`VERSION`) читают версию из `package.json` — руками не трогать.
- `cli/template/package.json.text` (пин `"umbot": "^X.Y.Z"`) и JSDoc-шапка `cli/umbot.js` (`@version`) — **ручные**, их синхронизирует релизный скилл. Если правишь их вне релиза, скажи об этом явно.

### Шаг 7: документация и CHANGELOG

Обязательная часть задачи (AGENTS.md раздел 6):

- `src/docs/json-format.md` — формат `flow.json`: новая нода, новое поле, новое условие, новое поведение генерации;
- `README.md` и CLI-раздел `src/docs/getting-started.md` — новая команда или флаг;
- `cli/README.md` — пользовательское описание CLI;
- `cli/AGENTS.md` — новая функция генератора, новое правило генерации или закрытый баг (секция «Исправленные баги»): это защита от повторения ошибки следующим агентом;
- `src/docs/deployment.md` — если менялись Dockerfile, файл деплоя или облачный сценарий;
- `CHANGELOG.md` — секция по правилам AGENTS.md раздела 6: `[Unreleased]` не использовать; писать в верхнюю невыпущенную секцию, а если её нет — спросить у пользователя версию и срок релиза.

## Анти-паттерны

1. ❌ **Не проверять генератор по его внутренностям.** Тест обязан смотреть на сгенерированный текст — пользователь получает именно его.
2. ❌ **Не исполнять данные из `flow.json`** (`eval`, `new Function`, `JSON.parse` шаблона с подстановками). `flow.json` может прийти откуда угодно.
3. ❌ **Не генерировать `fetch` без таймаута** — бот повиснет на ответе платформы и получит таймаут вебхука.
4. ❌ **Не вписывать токены в файлы, которые пользователь закоммитит.**
5. ❌ **Не перезаписывать непустую директорию без `--force`** — так теряют написанный вручную код.
6. ❌ **Не править один шаблон из восьми** и не считать задачу закрытой.
7. ❌ **Не менять поведение команды, не обновив `infoText`** — справка становится ложью.
8. ❌ **Не подгонять пин версии umbot под локальную сборку** — это ломает пользователей после публикации.

## Критерии успеха

1. ✅ Падавший тест на сгенерированном коде проходит, старые тесты `tests/cli/` зелёные
2. ✅ `npm run build` → `test` → `prettier` → `lint` чисто
3. ✅ Проект, сгенерированный вручную, устанавливается и собирается
4. ✅ Оба пути (`create` и `create from-flow`) и все затронутые шаблоны проверены
5. ✅ Документация обновлена (`json-format.md`, `cli/README.md`, `cli/AGENTS.md`, README/getting-started при изменении команд)
6. ✅ CHANGELOG обновлён в правильную секцию (не `[Unreleased]`)
